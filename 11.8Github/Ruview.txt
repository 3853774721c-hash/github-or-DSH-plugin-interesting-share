RuView（用 WiFi 信号"看"世界）
GitHub: https://github.com/ruvnet/RuView
官网: https://cognitum.one
103,000+ Star，13,000+ Fork，MIT 开源，Rust 为主（另有 TypeScript/React/WASM），2025 年 6 月创建

一、一句话
"π RuView turns commodity WiFi signals into real-time spatial intelligence, vital sign monitoring,
and presence detection — all without a single pixel of video."
——用普通 WiFi 信号的 CSI（信道状态信息）变化，实时感知空间里有没有人、人在哪、甚至呼吸和
心跳。全程不拍一个像素，不需要摄像头、不需要麦克风。

二、原理（为什么 WiFi 能"看见"人）
- ESP32 等开发板可以读出 WiFi 子载波的 CSI，即每个子载波的相位与幅度。
- 人体（呼吸、心跳、走动）会改变室内多径反射，从而在 CSI 的相位/幅度上留下微小起伏。
- 用信号处理 + 机器学习从这些起伏里反推：有人/没人、呼吸频率、心率、姿态/位置、
  甚至多人区分。
- 因此它的本质是"射频感知（RF sensing）"，不是光学成像。

三、能做什么
- 存在检测（presence detection）：房间里有没有人、离没离开。
- 生命体征监测：呼吸频率、心率（非接触、穿墙、黑暗中也能用）。
- 姿态/位置估计：pose-estimation（人体姿态推断）。
- 空间智能：spatial-intelligence（人处于空间的什么位置、在做什么）。
- 智能家居联动：官方支持 Home Assistant 集成（topic 里有 home-assistant）。
- MCP server：可以作为 Model Context Protocol 服务接给 AI 代理用。
- self-learning：项目里还带自学习/持续训练机制（"Dream Machine" 相关实验特性）。
- 固件同时支持 S3 8MB / S3 4MB / C6 4MB 等 ESP32 板型。
- 附带 LiDAR / mmWave 传感器数据摘要能力，可与雷达方案互补。

四、硬件与部署
- 需要 ESP32 系列开发板做 CSI 采集端（官方固件分 S3、C6 等 bundle）。
- 采集端把数据传给一台常开小主机（树莓派/迷你 PC/NAS）跑 Rust 端的处理与推理。
- 有 npm 工具链：npm install @ruvnet/ruview@0.9.2，或 npx @ruvnet/ruview --help；
  提供 CLI、SDK、doctor 自检命令、校准/基线会话。
- 需要按房间环境做校准（calibration）和基线（baseline）采集，否则效果不稳。

六、适合谁 / 注意事项
- 适合：Home Assistant 玩家、ESP32/IoT 折腾党、无线感知/雷达方向的学习者。
- 它不是一个"插电即用"的成品，而是固件 + 服务端 + 模型的一套工程，需要动手能力。
- 效果高度依赖房间布局、家具、路由器位置和校准质量，不同房间表现差异很大。
- 隐私/合规：虽然不采集图像音频，但"隔墙感知人体"本身敏感，商用/租房场景先确认当地法规，
  并在家里告知同住者。
- 100k+ Star 属于社区热度极高、但也伴随争议的项目，建议先看 issue 区再决定是否投入硬件。
